# EPIC-004: Multi-agent orchestrator, worker, and critic

## Goal

implement-task's loop runs as three roles with independently configurable model and effort: an orchestrator that delegates and triages, a worker subagent that implements, and a critic -- externalizable to a cheap non-Anthropic provider -- that reviews, with the rework loop and the external spend both bounded by hard, hook-enforced guardrails.

## In scope

- Flat per-role config keys and generated .claude/agents/*.md definitions for orchestrator, worker (per effort tier), and critic.
- A stdlib OpenRouter client with live model-catalog/pricing and balance lookups.
- The critic client: builds a review prompt from a task's acceptance criteria + diff + gate results, POSTs it, and parses structured findings -- with an Anthropic-subagent fallback when no external provider is configured.
- Pre-send safety: an explicit opt-in flag, a secret-pattern scan over anything sent externally, and a diff-size cap that halts rather than truncates.
- A budget guardrail: a credit-floor and burn-rate check against OpenRouter's balance before spending further.
- The critic-report triage taxonomy (accept, rework, escalate, follow-up task, second opinion, reject-with-rationale, split, bail out, halt) with a severity floor so only blocker-level findings trigger rework.
- Rework state: a 3-strike cap per task, a stale-report guard (discard a critic report if HEAD moved since it was generated), and a cap of one second-opinion call per task.
- Difficulty-driven worker effort/model tiering, selected once per task before the worker starts.
- A SubagentStop hook that denies a worker's completion if its diff leaves the task's declared file scope.
- The orchestrate-batch skill that wires all of the above into implement-task's loop and extends the end-of-batch summary with a per-agent model/effort/cost breakdown.

## Out of scope

- Per-agent provider routing for the orchestrator or the worker -- both stay Anthropic subagents.
- Parallel worker execution.
- A general-purpose multi-agent or multi-provider framework for other skills.
- Re-implementing the batch selection, core autonomous loop, interrupt taxonomy, context/token safety valve, follow-up-task limit, or auto-merge marker that the autonomous-batch-execution epic already owns -- this epic consumes that surface, it does not restate it.
- Self-hosting or fine-tuning any model.
- Changing the standing human-reviews-and-merges default.

## Success criteria

- [ ] Each role's model and effort level are set from config with no code edit.
- [ ] The critic runs on a configured non-Anthropic provider in the same session that runs Anthropic subagents for the orchestrator and worker.
- [ ] No external API call happens without the opt-in flag set, a clean secret scan, and a diff within the configured size cap.
- [ ] A task that gets kicked back by the critic a third time halts the automation and asks the human, rather than looping.
- [ ] A configured credit-floor or burn-rate breach halts the run and reports why.
- [ ] A worker whose diff leaves its task's declared scope is denied structurally, not just flagged.
- [ ] The end-of-batch summary reports, per task, which agent(s) ran it, at what model/effort, and at what cost.
