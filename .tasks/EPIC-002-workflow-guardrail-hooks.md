# EPIC-002: Workflow guardrail hooks

## Goal

Every mechanically-checkable guardrail and pre-PR gate in the workflow is enforced by a
`PreToolUse` hook, shipped per-project by `init-project`/`upgrade`, sharing one guardrail logic
module with the skills' own scripts.

## In scope

- A shared stdlib guardrails module (`.tasks/bin/guardrails.py`), vendored like `sync`.
- Hooks for the `SPEC-001 §Guardrails` list: deny `gh pr merge`, deny pushing task work to
  `default_branch`, deny force-push misuse.
- Structural edit guardrails: deny hand-edits inside `BEGIN:`/`END:` regions, deny epic `status`
  hand-edits except to `wont-do`.
- A branch-creation dirty-tree/naming gate.
- A pre-PR quality gate: `sync check` + `test_command` + `lint_command` + `format_command`.
- A repo-only scan denying a PR that still references concrete `SPEC-NNN`/`TASK-NNN` ids in the
  portable surface.
- A `SessionStart` hook injecting current board/in-flight-task context.
- Wiring all of the above into `upgrade`'s manifest and `config.md`-style additive merge.

## Out of scope

- Replacing any skill's STOP/approval flow — hooks are a backstop, not a substitute for judgment.
- A general-purpose hook framework for arbitrary project rules.
- Hook events unrelated to this workflow (model switches, subagents, notifications, etc.).
- Auto-fixing and committing on the model's behalf from within a hook.

## Success criteria

- [ ] A fresh `init-project` scaffold includes working hooks with zero configuration beyond the
      existing interview.
- [ ] Every guardrail in `SPEC-001 §Guardrails` has a hook that structurally denies its violation.
- [ ] `upgrade` updates hook files/registrations exactly like it updates skills/config.
- [ ] This repo's own `.claude/settings.json` runs all of them, including the one repo-only hook
      that is never copied to another project.
