# EPIC-003: Autonomous batch execution for implement-task

## Goal

`implement-task` can accept a validated batch of tasks — by epic, by numeric task-ID range, by an
explicit task list, or by a stopping task — and work through them with minimal human interaction,
interrupting appropriately, while human review of merges stays the default.

## In scope

- A deterministic batch-selection validation script (epic / numeric range / explicit list /
  stopping-task).
- An "announce, don't block" per-task plan step within an approved batch, replacing today's hard
  phase-1 STOP for tasks in the batch.
- Self-scheduled polling (via `ScheduleWakeup`) so the batch auto-continues to the next task once
  a PR merges, without manual re-invocation.
- An interrupt taxonomy (needs clarification, unexpected blocker, quality-gate failure surviving
  bounded retries, repeated guardrail/hook denial, `git`/`gh` infrastructure failure, context-usage
  threshold, token-usage threshold) routing isolated problems to "skip this task, continue" and
  systemic ones to "halt the batch."
- A configurable, capped policy for the LLM to create follow-up tasks autonomously mid-batch.
- An opt-in, critic-gated, per-batch-capped auto-merge path (`allow_auto_merge` repurposed from
  its current fixed `false`).
- An opt-in, project-wide TDD mode for `implement-task` phase 2.
- An end-of-batch summary: per-task outcomes, critic findings, follow-up tasks created, and
  token/cost usage.

## Out of scope

- Worker-agent parallelism or spawning subagents to execute tasks.
- General context-window management strategy (compaction, session boundaries, summarization) —
  only a minimal safety-valve interrupt is in scope here; the real strategy is a future spec/epic.
- Auto-merge as an unconditional default — it remains off unless a project opts in.
- A general-purpose critic-agent framework for other skills.

## Success criteria

- [ ] A human can hand `implement-task` an epic, a numeric task range, an explicit task list, or a
      stopping task, and get a deterministic validation before any work starts.
- [ ] A batch of well-specified tasks runs end-to-end with no manual re-invocation between a PR
      opening and the next task starting.
- [ ] Every named interrupt condition is recognized and routed correctly (skip-task vs.
      halt-batch).
- [ ] Auto-merge remains off by default; when enabled, every merge is gated by an explicit critic
      approval and a per-batch cap.
- [ ] The end-of-batch summary reports per-task outcomes, critic findings (if enabled), follow-up
      tasks created, and token/cost usage.
