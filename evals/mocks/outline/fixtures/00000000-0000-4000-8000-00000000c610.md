Status: approved

## Request

> Let's plan a feature: email myself the task list.

## Intent

Getting the open tasks into an inbox, so they can be read away from the terminal. Affects the `tasks.py` command line. Standard library only; the SMTP server comes from the `TASKS_SMTP` environment variable.

## Goals and non-goals

* Goal: `tasks.py mail <address>` emails the open tasks to the address.
* Non-goal: HTML email.

## Alternatives considered

* Printing the list and copying it into an email by hand: rejected, since it's the chore this removes.

## Design

A new `mail.py` module formats the open tasks as a plain-text body, and sends it with `smtplib`. Two slices, in this order:

1. **Format the open tasks as an email body.** `mail.py` builds the body: one line per open task, numbered as `tasks.py list` numbers them. Tested by a behavioral test that formats a scratch `tasks.json` and checks the text.
2. **Send the task list by email with `tasks.py mail`.** `tasks.py mail <address>` sends the body through the server in `TASKS_SMTP`. Needs the first slice. Tested by a behavioral test against a fake SMTP server that checks the message it received. Also a manual test, because only a person can see the message arrive in a real inbox: run `tasks.py mail` with a real SMTP server and the developer's own address, and check that the email arrives with the open tasks. The manual test doesn't block merge.

## Architecture change

Add `mail.py` to Components: it formats and sends the task list, and `tasks.py mail` calls it.

## Areas of concern

* A wrong `TASKS_SMTP` must fail with a clear message, not a traceback.

## Deferred

* Daily reminder emails: a scheduled send each morning. Deferred because nobody runs the CLI on a schedule yet. Brings it back: a request for reminders.
